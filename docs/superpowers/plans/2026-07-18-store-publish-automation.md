# Store Publish Automation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a `vX.Y.Z` tag, after the GitHub Release is cut, CI uploads the built extension to the Chrome Web Store and Firefox AMO and submits each for review.

**Architecture:** Extend the single-file workflow `.github/workflows/publish.yml`. The existing `publish` job builds, packages, attaches zips to the Release, then publishes two job outputs (`has_cws`/`has_amo`) and uploads the build as an artifact. Two new jobs, `store-chrome` and `store-firefox`, run after it (`needs: publish`), gated on those outputs, and upload the byte-identical artifact to each store. Store CLIs are pinned devDependencies invoked via `bunx`.

**Tech Stack:** GitHub Actions, Bun, esbuild, Vitest, `chrome-webstore-upload-cli` (bin `chrome-webstore-upload`), Mozilla `web-ext`.

## Global Constraints

- **Loopback-only extension; no runtime deps in the shipped bundle.** The store CLIs are **devDependencies** only — they never enter `dist/`.
- **No `console.*` in `src/`.** Not touched here; tests and CI config may do as they like.
- **Never log the bearer token or pairing code.** Not relevant to CI, but nothing in this flow may echo store credentials either — credentials are passed only via `env:` from `secrets.*`, scoped to the single job that uses them.
- **SHA-pin third-party GitHub Actions** with a `# vN` trailing comment, matching the existing file. Pinned SHAs to reuse:
  - `step-security/harden-runner@9af89fc71515a100421586dfdb3dc9c984fbf411 # v2.19.4`
  - `actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0`
  - `oven-sh/setup-bun@0c5077e51419868618aeaa5fe8019c62421857d6 # v2`
  - `softprops/action-gh-release@718ea10b132b3b2eba29c1007bb80653f286566b # v3.0.1`
  - `actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4`
  - `actions/download-artifact@d3f86a106a0bac45b974a628896c90dbdf5c8093 # v4`
- **`egress-policy: audit`** on every job (non-blocking) — matches the existing posture; do not switch to `block`.
- **Six repository secrets** the workflow reads (all new; repo-scoped): `CWS_EXTENSION_ID`, `CWS_CLIENT_ID`, `CWS_CLIENT_SECRET`, `CWS_REFRESH_TOKEN`, `AMO_JWT_ISSUER`, `AMO_JWT_SECRET`.
- **Test conventions** (from `test/unit/store-listing.test.ts`): `.ts` files in `test/unit/`; `import { readFileSync } from "node:fs"`, `resolve`/`dirname` from `node:path`, `fileURLToPath` from `node:url`, `{ describe, expect, test }` from `vitest`; `const ROOT = resolve(dirname(fileURLToPath(import.meta.url)), "../..")`.
- **Commands:** `bun run typecheck`, `bun run lint`, `bun run test`, `bun run build`, `bun run package`, `bun run check-build`.

- [ ] **Step 3: Rewrite the `publish` job in `.github/workflows/publish.yml`**

Replace the whole file with the following (the `store-chrome` / `store-firefox` jobs are added in Tasks 3–4):

```yaml
name: Publish Web Clipper

# Triggered by tags of the form `v0.1.0`. The tag version is written into
# package.json before building so the manifest version matches the tag, then a
# zip per browser target is attached to a GitHub Release. When store credentials
# are configured (see store/publishing.md) the store-chrome / store-firefox jobs
# upload the same artifacts to the Chrome Web Store and AMO and submit for review.

on:
  push:
    tags:
      - "v*"

permissions:
  contents: read

jobs:
  publish:
    name: Build + attach browser zips to the GitHub Release
    runs-on: ubuntu-24.04
    timeout-minutes: 15
    permissions:
      contents: write
    outputs:
      version: ${{ steps.version.outputs.version }}
      has_cws: ${{ steps.store_flags.outputs.has_cws }}
      has_amo: ${{ steps.store_flags.outputs.has_amo }}
    steps:
      - name: Harden Runner
        uses: step-security/harden-runner@9af89fc71515a100421586dfdb3dc9c984fbf411 # v2.19.4
        with:
          egress-policy: audit

      - name: Checkout
        uses: actions/checkout@9c091bb21b7c1c1d1991bb908d89e4e9dddfe3e0 # v7.0.0
        with:
          persist-credentials: false

      - name: Setup Bun
        uses: oven-sh/setup-bun@0c5077e51419868618aeaa5fe8019c62421857d6 # v2
        with:
          bun-version: latest

      - name: Install
        run: bun install --frozen-lockfile

      - name: Typecheck
        run: bun run typecheck

      - name: Lint
        run: bun run lint

      - name: Test
        run: bun run test
        env:
          CI: "true"

      - name: Resolve version from tag
        id: version
        run: |
          tag="${GITHUB_REF_NAME#v}"
          if ! [[ "$tag" =~ ^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$ ]]; then
            echo "::error::tag '$GITHUB_REF_NAME' did not parse as semver after stripping 'v'"
            exit 1
          fi
          echo "version=$tag" >> "$GITHUB_OUTPUT"
          echo "VERSION=$tag" >> "$GITHUB_ENV"

      - name: Stamp package.json with the tag version
        run: npm pkg set version="${{ steps.version.outputs.version }}"

      - name: Build bundles + manifests
        run: bun run build

      - name: Verify the build invariant
        run: bun run check-build

      - name: Lint the Firefox bundle (addons-linter)
        run: bunx web-ext lint --source-dir dist/firefox

      - name: Package per-target zips
        run: bun run package

      - name: Attach zips to the GitHub Release
        uses: softprops/action-gh-release@718ea10b132b3b2eba29c1007bb80653f286566b # v3.0.1
        with:
          files: dist-zip/*.zip
          tag_name: ${{ github.ref_name }}
          name: Web Clipper ${{ steps.version.outputs.version }}
          generate_release_notes: true

      - name: Build source archive for AMO review
        run: git archive --format=zip -o "dist-zip/source-${VERSION}.zip" HEAD

      - name: Detect store secrets
        id: store_flags
        env:
          CWS_CLIENT_ID: ${{ secrets.CWS_CLIENT_ID }}
          AMO_JWT_ISSUER: ${{ secrets.AMO_JWT_ISSUER }}
        run: |
          if [ -n "$CWS_CLIENT_ID" ]; then echo "has_cws=true" >> "$GITHUB_OUTPUT"; else echo "has_cws=false" >> "$GITHUB_OUTPUT"; fi
          if [ -n "$AMO_JWT_ISSUER" ]; then echo "has_amo=true" >> "$GITHUB_OUTPUT"; else echo "has_amo=false" >> "$GITHUB_OUTPUT"; fi

      - name: Upload build artifacts for the store jobs
        uses: actions/upload-artifact@ea165f8d65b6e75b540449e92b4886f43607fa02 # v4
        with:
          name: extension-build
          path: |
            dist/**
            dist-zip/**
          retention-days: 1
          if-no-files-found: error
```

Note the ordering: the source archive is built **after** "Attach zips to the GitHub Release", so the Release keeps only the two target zips (`dist-zip/*.zip` at attach time), while `source-<version>.zip` rides along only in the uploaded artifact for `store-firefox`.

Create `store/publishing.md` with exactly this content:

```markdown
# Publishing — Chrome Web Store + Firefox AMO

Releases are **tag-driven**. Pushing a `vX.Y.Z` tag runs
[`publish.yml`](../.github/workflows/publish.yml): it builds and packages the
extension, attaches a zip per target to a GitHub Release, and — once the store
credentials below are configured — uploads to the Chrome Web Store and Firefox
AMO and submits each for review.

The automated upload requires a **one-time manual bootstrap** (accounts, first
submission, and repository secrets). Until the secrets exist, a tag still cuts a
GitHub Release; the store jobs are skipped.

## One-time bootstrap

### 1. Accounts

- **Chrome Web Store:** register a developer account (one-off USD 5 fee) at
  <https://chrome.google.com/webstore/devconsole>.
- **Firefox AMO:** create a developer account at
  <https://addons.mozilla.org/developers/>.

### 2. First manual submission (creates the listing)

Build the artifacts locally (`bun run build && bun run package`), then:

- **Chrome:** in the Web Store developer console, create a new item and upload
  `dist-zip/nimbus-web-clipper-chrome-<version>.zip`. After it is created, copy
  the **item ID** — this is `CWS_EXTENSION_ID`.
- **Firefox:** in the AMO developer hub, submit
  `dist-zip/nimbus-web-clipper-firefox-<version>.zip` as a **listed** add-on. When
  prompted for source (the bundle is machine-generated), upload a
  `git archive --format=zip -o source.zip HEAD` archive. The add-on id is already
  fixed in the manifest (`web-clipper@nimbus-agent.dev`).

The first submission of each store must be done by hand; every release after that
is automated.

### 3. Credentials

- **Chrome (Google OAuth):** follow
  <https://github.com/fregante/chrome-webstore-upload-keys> to obtain a
  `CLIENT_ID`, `CLIENT_SECRET`, and `REFRESH_TOKEN` authorized for the Chrome Web
  Store API.

```

CI stamps the version into the manifest, builds, attaches the zips to a GitHub

each store's human review.

## When one store fails

`store-chrome` and `store-firefox` are independent jobs. If one fails (e.g. store
API downtime) the other stays green, and **Re-run failed jobs** retries only the
failed store — a succeeded Chrome upload never blocks an AMO retry.

Rare edge: if a store job fails *after* its upload already reached the store,
re-running it can report "version already exists". Recover by cancelling the
in-review submission in that store's dashboard, or bump the patch version and
re-tag.
